## 推荐节奏（不是交付承诺）

假设1位前端+1位交互设计、已有测试手机：第1个迭代做M2实机/存储/关键流程；第2个迭代收敛M3组件/状态；第3个迭代引入一个受控adapter；第4个迭代扩大真实任务接续。每个迭代建议1–2周，实际取决于反馈与平台权限，不把估算写成排期事实。

## 优先完成的三条闭环

1. 照片：真实导入/采集 → 选区/版本 → 中断接续 → 可确认导出。

2. 资料：文字/文件 → 原文与推断区分 → 任务封面控制 → 成果带来源。

3. 执行：意图 → 可检查计划 → 范围确认 → 实际回执 → 失败/取消/续接。

全套UI已经建立，后续不需要再建86个占位屏，而是把关键链路从原型提升到正式体验。

## 范围变更

新增支付、社交网络、App市场、复杂图像工具、后台云集群必须单独记录ADR/费用/许可/验收。先解决确认幂等、状态恢复和操作冲突，不能用增加页面数代替进展。
