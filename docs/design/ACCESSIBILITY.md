# 无障碍与替代操作

手势是默认交互，但不能是唯一入口。设置中可开启可点按的返回/活动/菜单控件；这不是给默认设计恢复底栏。已有键盘路径、焦点轮廓、语义按钮、输入标签和不活跃层 inert。

快捷键 H 活动、E 事件、A 能力、T 控制、M 菜单、Esc 返回。文本输入中不拦截这些字母；焦点按钮的空格交给按钮本身。

下一阶段验收：全部页面合理的焦点次序；弹层开启/关闭后的焦点归还；读屏能知道当前层级、错误和待确认对象；可达控件足够大；放大文字不截断；不通过颜色唯一表达成功/失败；减少动效关闭动态装饰；浏览器手势被系统抢走时不误提交。

本版有基础功能与部分自动检查，没有 WCAG/读屏/真实触觉认证。小字和触控目标需独立真机测试。

## UI-014：已有照片/备份确认的键盘边界

确认页激活或从最小化、其他任务、系统覆盖层返回时，焦点先落在「取消」。同一确认页重复同步状态不会从「接受」抢走焦点。Tab / Shift+Tab 只在现有取消与接受按钮间循环；有 inert 祖先、工作台目录、帮助层或系统覆盖层时，确认页不拦截它们的键盘操作。

Escape、取消按钮或既有右滑取消退回发起处。导入照片时，即使确认已进入照片任务，取消仍恢复之前的相册/拍摄页面与导入入口；接受的导入目标仍为照片工作区。Pulley 导出取消只在原照片上下文恢复原菜单命令。没有按钮入口的手势或 deep link 使用可见的当前任务容器作为焦点退路，不新增常驻控件。原图、版本、两侧草稿和手势阈值不因此改变。

焦点返回描述随每张确认和任务会话保留；取消后的旧文件选择结果不能重新导航或夺取焦点。这里的自动验收是桌面 HTTP-origin Chromium，不宣称读屏、手机软键盘或 WCAG 完整认证。
