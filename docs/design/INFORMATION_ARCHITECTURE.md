# 信息架构

## 两个空间，不是两套导航

手机内部是 **事件 / 活动 / 能力** 的连续水平系统空间。活动页居中；进入一件事后，内容覆盖系统空间，侧边可以把它推开或窥视。

手机外部是 **页面目录 / 真正运行的手机 / 规格与状态检查**。目录只给维护者检查全部页面，不是消费者手机里的侧栏。

## 结构

```
息屏 → 双击/电源 → 锁屏 → 侧边滑入 → 活动
系统空间：事件 ← 活动任务 → 发起能力
任何内容页：顶边 → 全局控制；底边 → 临时能力层
单个任务：根内容 → 子页面 → 明确确认
任何层级：侧边 → 把整个任务放回活动（保存层级）
```

事件显示已发生的本机动作和待决定内容，不混成聊天气泡。活动封面展示同一任务的状态，不是照片式最近使用列表。能力层从用户目的发起工作，不要求先打开某应用。

## 对象模型

`Task` 保存目标、输入引用、执行状态与待确认动作。`Session` 保存页面栈、阅读位置和未发送输入。`Artifact` 保存原始材料和派生版本。`Event` 是带时间与来源的观察。`Preference` 是用户明确同意的偏好，不是模型猜测。UI route ID 不能当成 task ID 或 artifact ID。

本版的 core 状态承接原片、笔记、整理、计时；suite 状态承接扩展表单和本机交互。动态封面在本次页面会话恢复；跨重载只恢复数据与草稿，不保证恢复所有动态封面的精确布局。

## 返回策略

根内容的内部右滑不冒充回主页；侧边才最小化整件事。子页面内部右滑退一层，确认页面左右分工明确。目录直接定位页面时会构建其父链，是验收便捷入口；从真实封面重新打开则恢复那件事的已有栈。

锁屏/息屏是 UI 状态，不会锁住用户真实系统；浏览器关闭不能称为云端继续。
