## 1. 改版定义

新版本不是“给 N9 加模糊”，也不是“做一个 iPhone 桌面再放 AI 应用”。视觉基础改为 iOS 26 的内容优先、功能层与内容层分离、柔和圆角、清晰字阶、按上下文呈现控制、连续且可中断的动效。产品结构仍然是以用户正在做的事为中心的 AI 手机。

保留：事件／活动任务／发起能力三个系统空间，边缘推开最小化，Peek 半推窥视与回推，活动封面的直接操作，顶部下拉上下文命令，任务栈、草稿、版本、确认快照以及中断接续。

重做：手机展示外壳、屏幕比例适配、页面布局、字体字重、色彩与材质、组件外观、图标、动效表现、辅助入口、新手引导、全界面目录与演示交付体验。

不做：复制 iOS 的应用图标桌面、Dock、灵动岛、Siri 光球或常驻聊天框；不增加固定底部导航；不更换仓库或重做已完成状态系统；不借视觉改版扩展支付、应用市场、真实云手机等业务。

## 2. 设计依据与使用边界

本方案以 Apple 官方 iOS 26 / WWDC25 设计说明为主要依据，结合 Apple 的基础触控建议与 W3C 对比度要求。网页中的玻璃只实现与这些原则相符的近似效果，不声称调用了原生 Liquid Glass，也不声称所有自定义系统手势是 iOS 标准。[S1][S2][S3][S4][S5]

### 2.1 玻璃用于功能层，不覆盖整个内容层

Apple 将 Liquid Glass 主要用于浮在内容之上的导航和控制，明确避免玻璃叠玻璃以及把正文列表整体玻璃化。[S1]

本项目的对应规则：照片、笔记、文章、清单和任务成果采用清晰、稳定的内容表面；顶端控制、上下文命令、短暂提示和操作面板才使用玻璃。确认正文以实底或高遮挡材质保证阅读，不能为了透亮牺牲确认对象、版本、目的地的可读性。

### 2.2 形状与排版是体系，不是统一放大圆角

Apple 的新设计强调圆角、内外边距的同心关系，并强化关键位置的字重和左对齐层级。[S2]

本项目采用少量统一的容器和控件形状；照片预览与外层面板按内外关系配套。长内容、设置列表不全部包进胶囊。标题与正文必须建立明确对比，不再使用大量超细字和微型说明。

### 2.3 动效表达来源与去向

从哪个对象发起，面板就应在视觉上与该对象相连；任务收起应让人知道它回到了哪个封面，恢复应返回同一任务，而不是每次播放全新的入场动画。[S2]

### 2.4 可读性优先于装饰

减少透明度、增加对比度、减少动效均为一等设计状态。Apple 原生材质可以响应相应系统设置；Web 原型必须自行实现并验证，不能宣称会自动获得同等行为。[S1]

## 3. 视觉系统

### 3.1 主方向

默认跟随系统提供浅色和深色两套完整外观。设计展示先用浅色主稿确立与旧版的明显差异，深色同步完成，不把深色作为浅色反相。

浅色：雾白页面、接近白色的内容表面、深石墨文字、局部玻璃控制、极少量低饱和青色强调。

深色：中性炭黑页面、略亮的石墨内容表面、近白文字；背景不整体染成蓝绿色。

壁纸主要用于锁屏、系统空间以及需要氛围的背景；长文阅读、设置和确认页面不让壁纸纹理穿过文字。

强调色是本次视觉候选，不代表新增品牌决定；不借用其他项目的品牌主色。

### 3.3 材质分级

**内容表面**：纯色／近实色，承载长文、照片、表单和任务结果。透明度不得影响编辑和阅读。

**标准控制玻璃**：用于短工具条、菜单和上下文操作；有限模糊、轻高光、柔阴影，并有稳定的可读性底层。

**媒体控制玻璃**：仅在照片等媒体背景上使用较通透效果，必须有局部遮罩和清晰前景。Web 中是本项目的视觉配方，不宣称等于 Apple 的 Clear API。

**保护性覆盖表面**：长消息、删除、备份恢复、授权等确认采用高遮挡或实色正文，保证复杂背景下仍然可读。

首版不实现实时复杂折射，不依赖全屏 WebGL 玻璃。可以对装饰性边缘做轻微动态高光，但不对正文、照片内容和所有组件持续施加折射。

## 4. 信息架构：保留三空间，去掉旧式应用切换器观感

固定空间关系：左侧「动态」SYS-02；中央「正在进行」SYS-01；右侧「开始一件事」SYS-03。保持横向相邻且不循环。内部编号、任务归属和深链接保持兼容。

### 4.1 正在进行

它不是 App 图标桌面，也不是四张等大窗口截图。首屏优先呈现一个正在继续的对象，以及两项其他任务的简洁摘要；更多任务向下展开。照片任务直接露出照片，笔记任务露出文字，专注任务露出时间；状态和操作依附于对象。

顶部为小日期与清晰标题。任务预览使用圆角内容表面，不将每项变成玻璃卡片。每项必须回答：这是什么、当前状态是什么、下一步能做什么。运行中、已暂停、待确认、已完成不能只用颜色区分。

显示顺序使用明确且稳定的规则，例如用户置顶与最近操作。页面正在被操作、键盘打开或手势进行时，AI 不得自动重排目标。

### 4.2 动态

采用轻量时间线，不是通知卡片无限堆叠。将「需要处理」与「已经完成」分组；按时间呈现细节，点击直接进入相关任务或成果。清理通知不等于删除任务，查看结果不等于授权下一步执行。

### 4.3 开始一件事

以动词组织能力：「处理一张照片」「记下一件事」「整理资料」「继续已有任务」。文字与语音输入属于发起意图的方式，不成为常驻主页中心。

未连接能力清楚标为未连接／界面预览；本机可用能力明确可操作。不要画一排应用图标让用户重新寻找 App。

### 4.4 底边能力入口

底边上滑仍唤出既有能力层，使用与 SYS-03 相同的能力内容和语义，不另建一套重复的导航。能力层关闭后恢复原任务。它是按需出现的覆盖层，不是常驻底栏。

## 5. 手势与状态兼容契约

本节区分保留的产品规则和重新设计的表现形式。下列不是 iOS 标准手势，而是本项目必须延续并实测的交互。[R2]

| 动作 | 保留的逻辑 | 新视觉与等价入口 |
| --- | --- | --- |
| 侧边向内推开 | 最小化整件任务，不等于返回上一页 | 当前内容轻缩放、圆角展开并露出真实任务空间；提供「收起任务」等价入口 |
| Peek 半推窥视 | 不松手可查看背景，回推还原 | 沿用当前内容实例，不重建会话或改变任务状态 |
| 三空间横滑 | 系统背景上切邻页，不循环 | 更轻的平移和标题过渡，保持固定空间顺序 |
| 内容内部右滑 | 返回当前任务的父级页面 | 父级视图跟手出现；独立返回入口，不能混成最小化 |
| 活动封面横滑 | 直接执行已定义的低风险动作 | 从对象边缘露出动作与文字，不用大块旧式色带 |
| 滚动到顶后新下拉 | 拉动选择当前上下文命令，松手执行 | 上下文玻璃菜单逐项高亮，并有相同内容的可点菜单 |
| 深拉固定 | 固定菜单，之后明确点按选择 | 呈现可停留面板，不再因松手执行当前项 |
| 顶边下拉 | 打开系统控制 | 柔和玻璃控制层，不伪造网络、亮度或硬件授权 |
| 底边上滑 | 唤出能力层 | 半屏到较大覆盖层，不变为 iOS 回主页手势 |
| 内容长按 | 继续交代当前对象 | 对象绑定输入面板；输入框与文本选择优先，不抢系统编辑 |
| 确认页左右滑 | 保留既有左侧接受、右侧取消和一次性消费 | 接受／取消词语始终明确，保留两个可点按钮；普通页滑动不可授权 |
| 图片内横滑 | 切换已有版本 | 图片连续过渡，当前版本标识固定；不自动生成新版本 |
| 锁屏侧滑、息屏唤醒 | 保留 UI 解锁与唤醒路径 | 新外观与简洁提示；不把滑动 UI 等同身份认证 |

### 5.1 判定与渲染分离

现有基线使用 360 × 672 逻辑坐标：侧边区域 18px、方向锁定 8px、最小化超过宽度 36%、三空间切换 75px、封面动作 48px、下拉第 1 项 68px／后续每项 56px、深拉固定 258px、页内返回和确认 110px、照片版本 65px、顶底覆盖层 125px、内容长按 600ms。以上是仓库现有值，非 Apple 数值。[R2]

首轮样板保留这些基线判定，先改外观；新增尺寸由统一视口坐标适配处理。后续任何阈值或命中区域校准必须单独记录、带旧／新对照与真机结果，不能藏在 CSS 改动中。视觉缩放不应意外缩小实际按钮命中区域。

### 5.2 取消与优先级

原生输入、文本选择、滑块等先于页面手势；多指、pointercancel、反向回推都必须有可靠取消路径。长文纵向滚动不能触发确认，页面离开和焦点变化不能隐式接受。

侧边最小化保存 taskId、stack、阅读位置和草稿。Peek 不重渲染已编辑对象；子页返回不结束 Task。封面上的本机动作不因为换样式就变成真实云服务控制。

### 5.3 浏览器与系统边缘冲突

网页不能接管真实 Android／iOS 的全局边缘手势；项目规范也明确这一限制。[R2] 桌面模拟器保留设备内的边缘操作区；移动端测试 Android 返回和 Safari 导航冲突，提供可发现的等价入口。不能宣称进入全屏或 PWA 即自动消除冲突。

### 5.4 上下文下拉命令的改造

用户文案使用「下拉操作」，不要求用户理解 Pulley。常用项建议 3–4 个，超出部分进入固定菜单；每项有图标、动词和明确高亮，拖回取消。

直接松手只执行可逆／低风险、本来已允许的操作。导出、覆盖、删除、恢复和未来对外动作必须打开既有确认，而不是利用手势直接绕过确认。确认页内部横滑继续作为既有快捷方式，UI 必须同时显示取消与具有具体含义的主按钮。

## 6. AI 的呈现方式

AI 是每个对象的能力，不是桌面上的一个发光入口。

在照片上继续交代时，面板显示「当前照片 · 版本 3 · 已选择天空区域」；在笔记上继续交代时，显示笔记名称与引用范围。显示选中对象／版本，可移除引用；并保留用户原文。用户应知道 AI 正在看什么，而不是依赖系统默猜。

输入、计划、运行、等待确认、暂停、完成和失败在视觉上明确区分。不得伪造精确百分比，不把浏览器被挂起的任务标为持续后台执行。

用户可检查执行步骤和实际事件，不展示或编造模型的私有思考。没有真实执行器时，计划和过程明确标为演示，不能用动效伪装网络请求或成功回执。

麦克风默认不持续监听；语音界面有可见的开始、停止、取消和校对，真实权限行为另行实现与验收。

## 7. 核心页面设计

### 7.1 照片工作区

照片成为画面主体。默认仅保留返回／收起、版本和更多等少量明确控制；不让大段页面标题占据照片上方。按需出现的编辑工具不作为全局底部导航。

轻触或菜单进入已有局部选择，版本和裁切独立可达；长按／继续交代入口绑定当前对象。原图与当前版本的比较有稳定标识，拖动对比滑杆时绝不触发返回。版本记录改为缩略图与说明组合的检查层，不复制旧式文字长列。

导出前展示固定版本、预览、比例与目的地；确认是下载实际结果，不是删除原图。原始导入、编辑版本和生成结果在信息模型上保持区分。RAW／DNG 处理与真实生成模型属于后续能力，当前 UI 改版不宣称已经具备。

### 7.2 笔记与资料

以高可读的纸面／阅读表面为主，标题、正文、来源和更新时间层级明确。整理动作产出独立结果，不把整理稿冒充原文。编辑时键盘上方只有必要控制；工具层随键盘与可视视口调整，末行内容不能被遮住。

资料总览采用清晰分组、文件缩略图和最近成果；不用一张张重复大卡片制造高度。清单采用足够大的勾选区域，操作后保留阅读位置。

### 7.3 任务详情

任务标题下面先显示一句真实状态，再显示当前阶段、输入来源与暂停／继续等动作；详细步骤可展开。不默认展示控制台、日志墙、模型型号和虚假的倒计时。

结果、输入、版本、授权和活动记录均可检查，但不同类型信息分组，不把整个任务埋在聊天记录里。跨空间切回任务应保持原对象和当前位置。

### 7.4 执行确认

统一为「可阅读的确认单」：对象、版本、动作、目的地、影响范围、本机或真实服务边界。长内容拥有独立滚动区，取消与主操作不随正文滚出；大字号时可改为全高页面。

主按钮必须具体，例如「导出这个版本」「恢复这份备份」「确认本机预览」。保留固定 payload／候选归属／一次性消费；确认中有新版本出现也不能替换已展示内容。取消恢复草稿；存储失败保留可重试确认，不能直接显示成功。

### 7.5 云端空间

用服务与任务状态解释云环境，不默认在手机内再嵌入一台 Android 桌面。个人环境、任务、文件、连接和权限是核心；远程桌面只作为后续可能的高级接管入口，不纳入本次开发。

默认忠实显示当前未连接状态；本机文件不标云文件。周期任务仍是草稿时必须显示「未启用」，预算字段不能暗示真实账单，未授权动作不能暗示已执行。

### 7.6 系统控制、设置与锁屏

系统控制采用分组浮层，能力与实际平台权限相符。设置使用熟悉的分组列表；手势、外观、数据与隐私、AI 连接和无障碍有清晰标题与状态。

锁屏显示时间、必要任务摘要与清晰唤醒／解锁提示；不复制 iPhone 特定硬件缺口和动态岛，也不展示虚假的认证通过。涉及个人摘要的显示粒度作为明确偏好，不默认暴露敏感内容。

## 8. 全量范围：86 个编号完整保留

## 9. 三条必须先完成的闭环

### A. 照片闭环

导入照片 → 调整与生成本机编辑版本 → 查看原图对比 → 边缘收起 → 操作另一任务 → 恢复照片 → 检查固定版本并导出。

当前使用真实已有的本机能力，不以生成预览替代实际结果。验收：图像／版本与导出一致，原片未覆盖，草稿／选区／阅读状态按现有契约保留，取消不导出。

### B. 资料闭环

输入笔记 → 发起本机整理 → 回到正在进行 → 封面暂停／继续 → 查看整理稿与原文 → 导出结果。

验收：原文独立保留、状态真实、来源可查、恢复位置正确，不把前台计时和处理冒充跨设备云执行。

### C. 确认闭环

填写消息草稿或执行要求 → 检查对象／范围 → 打开固定内容确认 → 取消并保留草稿 → 再次明确确认 → 查看本机预览记录。

真实服务尚未连接时，完成的是可用的确认与预览闭环，不是真实发送闭环。连接能力属于 M4，不混进本次 UI 验收。

## 11. 动效与反馈

以下为本项目测试起点，不是 Apple 官方动效时长。

按压反馈约 100–160ms；小型菜单约 180–260ms；页面／任务收放约 260–380ms。跟手阶段不套固定时长，位置随手指更新；松手后才决定提交或回弹。反向拖动、连续操作、键盘出现和任务状态更新不能被不可中断动画阻挡。

照片与任务缩略图尽量形成连贯过渡；菜单在其触发源附近展开；恢复任务回到同一对象。性能不足时先关闭装饰折射与动态模糊，而不是增加操作延迟。

触觉反馈只在真实平台能力支持时使用，不作为判断成功与否的唯一渠道。减少动效模式取消弹性、放大缩小和装饰视差，仍提供清晰位置变化、文本和状态标识。

## 12. 无障碍、兼容性与性能

正文对比度按 WCAG 2.2 AA 的至少 4.5:1、大文字至少 3:1 作为 Web 验收目标；最终在实际叠加背景上测量，不能只测 token 色板。[S5]

浅色、深色、减少透明度、增加对比度和减少动效分别检查。200% 字号下长消息、设置、任务详情可阅读，确认操作可达，不因容器固定高度截断正文。任务状态不得只靠青／红／橙颜色传达。

保留键盘与读屏语义：可见焦点、对话框标题、取消初始焦点、焦点限制与恢复、Escape 取消、状态适度播报。不用纯 Canvas 绘制整个系统 UI。图标按钮必须有名称，不强迫用户掌握手势才能完成重要操作。

移动端必须测试 iOS Safari 与 Android Chrome，记录具体设备、系统与浏览器版本。自动化浏览器的绿灯不等于软键盘、VoiceOver、TalkBack、系统字号或边缘冲突已经真机通过。

性能以有记录的测试设备为准：跟手操作目标约 60fps，采样帧耗时与长任务，明确失败条件；不声称所有设备都能稳定达到。首版限制大面积动态模糊、减少多重覆盖，后台／隐藏任务停掉装饰动画。不以精确电量或功耗改善百分比作未经测量的承诺。

离线单文件不依赖外部 CDN、远程字体或模型。文件导入、持久化、相机、语音和下载在不同浏览器中的限制必须如实反馈，不能依靠假成功提示掩盖。

## 13. 网页展示方式

**手机体验模式**：直接占用浏览器可用视口，不再在真实手机里画一个厚重手机壳；适配安全区、键盘与动态浏览器工具栏。无法取得全屏时仍可使用。

**桌面展示模式**：保留中性薄边框的拟真手机，去掉 N9 风格彩色机身、夸张上下边框和装饰标识；不复制特定 iPhone 外壳。

**设计检查模式**：左侧目录和右侧说明默认可收起，明确处于设备外部。首次打开优先看到产品本身，而不是工程目录。完整目录、状态检查、手势说明仍随时可进入。

## 14. 工程迁移原则

现有 src/data/screens.json 继续作为界面目录事实来源。改版主要在模板、样式、组件呈现和薄视图适配层完成；不在同一个变更中重写确认、导入、恢复和存储逻辑。

保留 taskId、stack、版本、草稿与固定 payload 的行为契约。尽量保留既有 action 和路由接口；确有调整必须有明确映射和旧数据测试，不通过清空 localStorage 解决迁移问题。

参数按 surface、text、accent、spacing、radius、motion、material 的语义组织，而不是新增大量页面专属硬编码。避免给旧全局样式持续叠覆盖选择器。

构建仍产出可独立运行的 dist/index.html；不直接手改 dist。未来原生版本可根据相同语义对接原生控件，不把 CSS 玻璃近似效果当原生实现。

建立对照快照：旧版作为回归参考留存，新版逐批覆盖。视觉断言预期发生变化，需人工检查新基线；行为断言不能为迁就新版错误而删除或放宽。

**范围**：86 个编号有迁移记录与正常入口；没有通过隐藏复杂页面、错误页或设置页减少范围。

**数据**：改版与主题切换不丢原文、草稿、任务、版本；已有确认绑定原 payload 和候选；新文件、异步校验及新版本不能偷换旧确认。

**真实性**：本机、演示与未来真实服务的状态清楚；没有未连接却显示发送成功、开通成功、已付款或已同步的情况。

**可用性**：用约 5 名未接触项目的体验者做形成性测试，观察是否能在不读长说明的情况下开始任务、收起恢复和取消确认；目标约 80% 首次完成，记录样本和问题，不把小样本结果当统计保证。

**交付**：下载 HTML 字节完整、实际可打开；在线地址实际加载成功并完成关键流程后才标为已部署。附准确源码提交与构建版本，不仅给源码链接。

# 附录 B：首轮回归用例

| 用例 | 操作 | 必须保持的结果 |
| --- | --- | --- |
| Peek 撤回 | 编辑笔记后半推侧边再推回 | 不丢文字、任务和焦点上下文，不产生新任务 |
| 跨任务接续 | 停在照片版本页后收起，再处理笔记，再回照片 | 回到原任务栈和版本，不回到初始相册 |
| 下拉取消 | 菜单高亮某项后反向推回 | 不执行该项，也不误触背景按钮 |
| 深拉固定 | 超过固定阈值后松手，再点击菜单 | 松手不执行，明确点击才执行 |
| 长消息阅读 | 纵向拖动、键盘翻页、放大字号 | 正文与末尾说明可读，不触发接受 |
| 固定确认版本 | 确认 A 打开后产生版本 B，再接受 A | 始终操作 A 的已展示快照 |
| 候选归属 | 选择文件 A，切任务选择 B 并取消，再接续 A | A 不取用 B；取消或消费的候选不可重放 |
| 存储失败 | 备份恢复确认时写入失败，之后重试 | 原资料不被部分覆盖；保留同一有效确认 |
| 对比滑杆 | 拖动照片对比滑杆至两端 | 只改变比较位置，不返回／最小化 |
| 中文输入 | 输入法组合中滑动、换焦点、关闭能力面板 | 不提前提交文字，不隐式发送或清空草稿 |
| 辅助操作 | 只使用键盘或读屏导航核心闭环 | 关键动作、取消和恢复均可完成 |
| 主题切换 | 在编辑、确认与任务暂停状态间切换浅／深 | 只改变呈现，不重置任务或消费确认 |
| 离线启动 | 完整 HTML 断网打开 | 本机可用功能不依赖 CDN 或远程字体 |
| 线上交付 | 打开最终 URL 并完成导入／编辑／恢复／导出 | 不把 404、源码页或 CI 配置文件当成成功部署 |
